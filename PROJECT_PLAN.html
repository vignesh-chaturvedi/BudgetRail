Primary KPI

The five-beat proof loop

Every beat must produce a receipt or a deterministic denial record.

01 / GRANT

Owner sets the rail

Grant the registered agent 2 USDC of fixed authority with a 24-hour expiry.

02 / CHALLENGE

Merchant returns 402

The agent requests a useful resource and receives exact payment requirements.

03 / PAY

Agent spends 0.10

BudgetRail validates every field, signs through the delegation, and unlocks the resource.

04 / REJECT

3 USDC is denied

The transfer exceeds the remaining authority, so the resource stays locked.

05 / REVOKE

Kill switch works

The owner revokes the delegation. The agent's next 0.10 USDC attempt fails.

Risk register

What could derail the build

The schedule is ordered by uncertainty, not visual polish.

Critical

x402 transfer shape

The standard tooling may assume a normal token transfer. Retire this risk in Phase 1 with a self-hosted verifier adapter as the documented fallback.

High

Scope inflation

No wallet platform, token, swaps, multichain layer, or conversational transaction builder. Preserve the single proof loop.

Critical

Agent key exposure

Server-only disposable key, redacted logs, no client bundle access, and secret scanning before every public release.

High

Replay/malicious challenge

Validate host, cluster, mint, amount, recipient, nonce, and expiry. Never let the model decide transaction fields.

Medium

Registry SDK boundary

Keep the 8004 registry's legacy SDK types inside an isolated adapter so the core remains on @solana/kit.

Medium

Cluster availability

Make mint and cluster configurable, use Surfpool fixtures, and approve mainnet only after safety tests pass.
